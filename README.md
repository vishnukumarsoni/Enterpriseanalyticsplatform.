# Enterprise Sales, Customer &amp; Revenue Analytics Platform

*Enterprise Analytics Hub*

An end-to-end analytics platform: synthetic data generation → validation →
ETL → PostgreSQL → SQL analytics → Python/ML → FastAPI → React dashboard.

## 1. Project Overview

This project simulates a real enterprise analytics product for a retail/
e-commerce company, covering revenue, profit, customer, product, regional,
and salesperson performance, plus churn prediction, RFM segmentation, and
revenue forecasting.

## 2. Business Problem &amp; Objectives

See [`docs/business_requirements.md`](docs/business_requirements.md) for the
full requirements. In short: give management one trustworthy place to see
revenue/profit health, spot at-risk customers before they churn, and compare
performance across products, regions, and salespeople.

## 5. Dataset

Generated by `etl/generate_data.py`: 10,500 customers, 550 products, 120
employees, ~106,000 orders, ~7,500 returns, over 3 years of history.
Customers have a persistent latent activity level and ~30% are modeled as
genuine churners (they stop buying partway through the period) — this is
what makes the churn model and RFM segments meaningful rather than random.

## 7. ETL Pipeline

```bash
cd etl
python generate_data.py   # generates raw CSVs into data/raw/
python etl_pipeline.py    # extract -> transform -> validate -> load
```

Validation results land in `data/reports/data_quality_report.csv`; execution
logs in `data/reports/etl_execution.log`. The load aborts if any rule FAILs.

## 9. Python Analysis &amp; ML

```bash
cd ml
python rfm_analysis.py       # RFM scoring -> data/reports/rfm_segments.csv
python churn_model.py        # trains 3 models, picks best by ROC-AUC
python forecasting.py        # Holt-Winters revenue forecast + backtest
python model_evaluation.py   # prints/saves a consolidated metrics summary
```

The churn model uses a **time-split** feature/label design (features from an
observation window, label from a strictly later holdout window) specifically
to avoid label leakage. Achieved ROC-AUC ≈ 0.77 with Random Forest on this
dataset — reported honestly, not inflated.

## 12. Installation (local, without Docker)

### Prerequisites
- Python 3.11+, Node.js 20+, PostgreSQL 16

### Database
```bash
createdb enterprise_analytics
```

### Backend
```bash
cd backend
pip install -r requirements.txt
cp .env.example .env   # edit DATABASE_URL if needed
cd ../etl
python generate_data.py
python etl_pipeline.py
cd ../ml
python rfm_analysis.py && python churn_model.py && python forecasting.py
cd ../backend
uvicorn app.main:app --reload --port 8000
```

### Frontend
```bash
cd frontend
npm install
cp .env.example .env   # VITE_API_BASE_URL=http://localhost:8000
npm run dev
```

- API: http://localhost:8000 (docs at `/docs`)
- Frontend: http://localhost:5173

## 13. Docker Setup

```bash
docker compose up --build
```

- Postgres: `localhost:5432`
- API: `http://localhost:8000`
- Frontend: `http://localhost:8080`

After the containers are up, run the ETL and ML scripts once against the
containerized Postgres (`DATABASE_URL=postgresql+psycopg2://postgres:postgres@localhost:5432/enterprise_analytics`)
to populate data, since the dataset generation step is not run automatically
inside the container.

The `/api/insights` endpoint and the **Reports** dashboard page generate

## 17. Future Improvements

- Add a scheduled job (e.g. Airflow/cron) to re-run the ETL and retrain the

- Add automated data generation for a "current day" so the dashboard shows
  ongoing, incrementing history rather than a static historical dataset.
